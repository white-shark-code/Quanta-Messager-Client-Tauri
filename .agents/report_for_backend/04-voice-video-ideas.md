# 04 — Голосовые / видео сообщения (идеи на будущее)

**Приоритет:** 🟢 low
**Статус:** отложено, отдельный этап

> В текущем API медиа-вложения поддерживаются только как обычные файлы
> (`docs/media.md`). Голосовые и видео — естественное расширение этой модели,
> но требуют доработок и UX-решений.

---

## Идея 1 — Голосовые сообщения как обычные медиа

**Самый простой вариант.** Голосовое — это просто `.ogg` / `.opus` файл,
записанный через `MediaRecorder API` на фронте, отправленный через существующий
media-pipeline (`POST /private-message/{chat_id}/media/upload` + `media_ids`).

### Плюсы

- Не требует изменений бекенда.
- Уже работает с любыми `mime_type`.
- Шифрование и подпись — те же.

### Минусы

- Нет UI для плеера (waveform, прогресс-бар, скорость воспроизведения).
- Нет индикатора «прослушано».
- Большой размер блоба (сжатие Opus решает).

### Что делаем на фронте

- Запись через `MediaRecorder` (`audio/ogg; codecs=opus`).
- Визуализация waveform через `AudioContext` + `AnalyserNode` (опционально).
- Плеер — кастомный компонент с прогрессом.

## Идея 2 — Видео сообщения (кружки)

Аналогично — это `.webm` файл, записанный через `MediaRecorder` (с `video/webm; codecs=vp9` или `video/webm; codecs=h264`).

### Нюансы

- Размер файла быстро растёт → нужен лимит `MAX_MEDIA_SIZE_BYTES`.
  Сейчас 50 MB (см. `settings.MAX_MEDIA_SIZE_BYTES`).
  Видео-кружок 30 сек ≈ 1-3 MB в WebM/VP9, ОК.
- На mobile нужен доступ к камере — Tauri permission для Android.

### Плюсы

- Тоже не требует изменений бекенда.

## Идея 3 — Real-time звонки (audio/video call)

**Сложный вариант.** Требует:

- WebRTC на фронте (или Tauri-friendly обёртка).
- Сигнальный сервер (можно через бекенд, но это расширение API).
- TURN/STUN-сервер для NAT traversal.

### Почему пока не делаем

- Выходит за рамки «мессенджер с E2E».
- WebRTC + Tauri на Android — пока экспериментально.

### Что можно сделать в перспективе

- Вынести сигналинг в отдельный WS-эндпоинт `/ws/calls/{chat_id}`.
- Использовать **insertable streams** в WebRTC для E2E-шифрования (Double Ratchet / MLS).
- Для MVP звонков можно использовать libp2p или LiveKit как managed-решение.

## Идея 4 — Голосовые «как в Telegram» (прогрессивное воспроизведение)

Telegram подгружает голосовое по чанкам и начинает воспроизведение ещё до полной загрузки.

### Реализация

- Бекенд поддерживает `Range` header для media download:
  ```
  GET /private-message/media/{media_id}
  Headers: Range: bytes=0-65535
  Response: 206 Partial Content
  ```
- Фронт через `fetch` с `ReadableStream` подгружает по чанкам, дешифрует
  и скармливает в `<audio>` через `MediaSource` API.

### Зачем

- UX улучшение: мгновенный старт воспроизведения.
- Экономия трафика для длинных голосовых.

### Что просим от бекенда

- Поддержка `Range` для `/private-message/media/{media_id}` и
  `/group-message/media/{media_id}`.
- Заголовки `Accept-Ranges: bytes`, `Content-Length`, `Content-Range`.

## Идея 5 — Push-to-talk (рация)

Кнопка удерживается → запись → отпускание → отправка.
Реализуется целиком на фронте через `MediaRecorder.start()/stop()`.
Не требует изменений бекенда.
